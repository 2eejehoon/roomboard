# Research: 시각 품질 개선

## R1. 조명 환경: HDRI를 받지 않는다

- 사실: 지금 장면에는 직접 조명이 없고 drei `Environment files=…hdr`(테마당 1.6~1.8MB)가 빛을 전부 맡는다.
  배경은 단색 `#d9cbb8`이고 HDRI는 배경으로 보이지 않는다. 첫 로딩 에셋 약 3MB 중 HDRI가 절반 이상이다.
- **Decision**: HDRI 파일을 지우고, 테마 `look`의 해(방향광)·주변광(반구광)과 drei `Environment`의 자식
  `Lightformer`(내려받기 없는 반사 환경)로 비춘다.
- **Rationale**: 로우폴리 단색 재질은 HDRI의 세밀한 반사를 거의 쓰지 않는다. 직접광이 있어야 그림자가 생긴다(FR-002).
  첫 로딩이 테마당 약 1.7MB 줄어 SC-001 여유가 커진다.
- **Alternatives**: HDRI 유지 + 직접광 추가 — 용량이 그대로이고 두 빛이 겹쳐 밝기 맞추기가 어렵다. drei 프리셋 —
  외부 CDN에서 받아 기각.

## R2. 그림자

- **Decision**: 해 하나만 그림자를 만든다. 그림자 카메라를 테마 경계(`bounds`)에 맞추고, 지도 크기는 휴대폰(굵은 포인터)
  1024, 데스크톱 2048. 가구·아바타는 그림자를 드리우고 바닥은 받는다.
- **Rationale**: 움직이는 아바타 그림자가 필요해 정적 접촉 그림자로는 부족하다. 그림자 하나는 저사양에서도 감당된다.
- **Alternatives**: drei `ContactShadows`를 매 프레임 — 비용이 더 크다. 아바타 밑 원형 그림자 — 가구 그림자가 없다.

## R3. 벽·하늘·바닥

- **Decision**: 실내 테마(카페·도서관)는 경계 4면에 안쪽만 그리는 벽(단면 재질)을 둔다. 카메라가 벽 밖으로 나가도 뒷면이
  그려지지 않아 시야를 가리지 않는다. 정원은 하늘색 배경과 안개로 경계를 흐린다. 색은 테마 `look`의 값이다. 새 모델·텍스처 없음.
- **Alternatives**: 벽 모델 에셋 추가 — 용량과 출처 관리가 늘어난다.

## R4. 아바타가 검게 보이는 원인

- 사실: `public/assets/characters/char-0*.glb` 8개 모두 `Skin` 재질 기본색이 0.013(선형, sRGB 약 #1F1F1F)이다. 눈(`Face`)만 흰색이다.
  조명을 바꿔도 피부는 검게 남는다.
- 가공(`scripts/fetch-assets.sh`: 애니메이션 거르기, glTF-Transform `prune`·`resample`·`meshopt`)은 재질 색을 바꾸지 않는다.
  따라서 원본도 같은 색이다(2026-11-11 원본을 다시 받으려 했으나 Google Drive 할당량 초과로 직접 비교는 못 함).
- **Decision**: 불러올 때 `Skin` 재질 색을 아바타별 피부색 표(8개, data-model)로 바꾼다. 에셋 파일은 그대로 둔다
  (CC0라 수정 가능하고, 다시 받을 때 가공을 바꿀 필요가 없다).
- **Alternatives**: 에셋 파일 색을 바꿔 다시 만들기 — `assets.sha256`과 가공 스크립트를 함께 바꿔야 해서 더 크다.

## R5. 화면 디자인 기준

- **Decision**: Astryx `theme-neutral` 토큰(글자 크기·간격·색)과 컴포넌트(Card, Button, TextField, Banner)만 쓴다.
  화면에 남은 인라인 스타일(예: 아바타 이름표, 테마 그림 크기)은 토큰 값으로 바꾼다. 방 목록 항목은 Card(테마 그림 + 제목 + 인원).
  방 화면의 머리글·채팅은 반투명 면 위에 둔다.
- **Rationale**: 새 디자인 시스템 없이 일관성(FR-005)을 얻는다. 001 T100~T106에서 이미 들였다.

## R6. 기준 화면과 판정

- **Decision**: `tests/e2e/visual.spec.ts`가 [contracts/visual-baseline.md](contracts/visual-baseline.md)의 화면을 찍어
  `test-results/visual/`에 남긴다. CI는 성공해도 이 폴더를 결과물로 올린다. 픽셀 비교는 하지 않는다(소프트웨어 렌더링이
  기계마다 달라 001 미리보기 그림도 해시에서 뺐다). 자동 판정은 밝기·대비·가로 스크롤·터치 크기만, 모습은 운영자가
  미리보기 배포(T097)를 휴대폰으로 보고 판정한다(SC-001).
- **Alternatives**: 스크린샷 픽셀 비교 — SwiftShader 렌더가 흔들려 거짓 실패가 난다.

## R7. 3D 품질의 자동 측정

- 아바타 밝기(SC-002): 내 아바타를 화면 가운데 두고 머리 영역의 평균 밝기를 화면 평균과 비교한다.
- 그림자(FR-002): 그림자를 끈 장면과 켠 장면에서 가구 바로 아래 바닥 영역 밝기 차이.
- 둘 다 테스트 훅으로 장면 상태를 바꾸지 않고 캔버스 픽셀을 읽는다(`preserveDrawingBuffer` 없이 스크린샷으로).
