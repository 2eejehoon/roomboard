# Feature Specification: 자체 제작 캐릭터 (오리지널 스타일, 기술 동작, 성능 예산)

**Feature Branch**: `claude/005-own-characters`

**Created**: 2026-11-27

**Status**: Draft

**Input**: User description: "005 자체 제작 캐릭터: 지금의 Quaternius 캐릭터 8종을 우리가 생성 스크립트로 직접 만든 오리지널 캐릭터로 바꾼다.
오리지널 스타일 가이드, 커스터마이즈 범위, 애니메이션 목록(이동 + 004 기술 + 006 기술 자리, 타격감에 맞는 선딜·활성·후딜 포즈),
숫자로 적은 성능 예산과 측정 방법, LOD와 2D 대체 화면. 스타일은 시안을 실제 방 화면에 넣어 운영자가 고른다. 확정한 스타일 가이드는 맵 세션도 쓴다."

## 범위

- 방과 경기장에 보이는 모든 사람(내 아바타, 다른 참가자)의 **3D 모습과 동작**을 바꾼다. 지금 캐릭터(외부 무료 팩 8종)를 모두 걷어낸다.
- 캐릭터는 저장소의 생성 스크립트로 우리가 직접 만든다(헌법 제품·품질 제약, 판례 2026-11-27-own-assets). 스크립트를 다시 돌리면 같은 파일이 나온다.
- 운영자 결정(2026-11-27): 디자인 품질과 성능이 가장 중요하다. 시간이 걸려도 가장 좋은 안을 고른다. 캐릭터를 먼저, 맵(방 인테리어·경기장)은 따로 병렬로 한다.
- 이 스펙이 정한 스타일 가이드([style-guide.md](style-guide.md))는 맵 작업도 따른다. 캐릭터와 공간이 한 화풍으로 보여야 한다.
- 범위 밖:
  - 이용자가 모습을 직접 고르는 화면(모습 고르기, 저장). 005의 모습은 지금처럼 기기 키에서 정해진다(FR-010).
  - 방 인테리어·가구·경기장 블록의 새 모델(맵 작업이 맡는다).
  - 새 기술, 판정, 조정표 수치의 변경(004, 006이 정한다). 005는 그 기술을 보여 주는 동작만 만든다.
  - 효과음.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 방에 들어가면 우리만의 캐릭터가 보인다 (Priority: P1)

방문자가 방에 들어가면 나와 다른 참가자가 한 화풍의 오리지널 캐릭터로 보인다. 몸 비율·얼굴·색이 방의 아늑한 분위기와 어울리고,
여러 사람이 모여도 서로 구별된다. 걷기·달리기·뛰기·서 있기가 자연스럽다.

**Why this priority**: 사람이 이 서비스에서 가장 오래 보는 대상이고, 운영자가 캐릭터를 맵보다 먼저 하기로 했다.

**Independent Test**: 방에 브라우저 5개로 들어가 기준 화면(데스크톱·휴대폰)을 찍어 운영자가 판정하고, 모습마다 성능 예산(FR-020~FR-027)을 자동으로 잰다.

**Acceptance Scenarios**:

1. **Given** 참가자 5명이 있는 카페 방, **When** 첫 화면을 보면, **Then** 모두 스타일 가이드의 비율·팔레트·재질을 따른 캐릭터로 보이고, 옆 사람과 모습(머리 모양·색·옷)이 다르다.
2. **Given** 내 아바타가 서 있다가 움직일 때, **When** 걷기 → 달리기 → 점프 → 멈춤을 하면, **Then** 동작이 끊기지 않고 이어지며(전환 0.2초 안팎) 발이 바닥을 미끄러지듯 보이지 않는다.
3. **Given** 어느 테마 방이든, **When** 아바타 얼굴을 보면, **Then** 눈·피부·머리카락이 구분된다(003 SC-002를 계속 지킨다).

### User Story 2 - 기술마다 몸이 그 기술을 한다 (Priority: P1)

경기장에서 잽·강펀치·던지기·방어·구르기·공중 점프·복귀기를 쓰면 캐릭터 몸이 그 기술의 동작을 한다. 때리는 순간의 자세가 분명하고,
맞으면 움찔하고, 날아가면 몸이 뒤집힌다. 판정 시각은 바뀌지 않는다.

**Why this priority**: 004의 손맛(US2)은 지금 몸 동작 없이 이펙트만으로 낸다. 몸이 따라와야 "때리는 맛"이 완성된다.

**Independent Test**: 기술마다 정해진 상황을 재생해 그 순간의 동작 이름과 자세 단계(선딜·활성·후딜)를 상태 값으로 확인하고, 운영자가 화면을 보고 판정한다.

**Acceptance Scenarios**:

1. **Given** 경기장의 두 사람, **When** 한 사람이 잽을 누르면, **Then** 그 순간 팔을 뻗은 활성 자세가 보이고, 타격 정지 동안 그 자세로 멈췄다가 다시 쓰기 시간 동안 원래 자세로 돌아온다. 판정은 누른 순간 그대로다.
2. **Given** 강펀치를 누르고 있는 사람, **When** 모으는 동안, **Then** 몸을 뒤로 당긴 선딜 자세가 모은 시간에 따라 커지고, 떼면 활성 자세로 바뀐다.
3. **Given** 잽 1·2·3타, **When** 연타하면, **Then** 세 타의 자세가 서로 다르고 3타가 가장 크다.
4. **Given** 맞은 사람, **When** 경직 중이면, **Then** 움찔 동작을, 넉백으로 날아가면 날아가는 동작을, 벽에 낙법하면 낙법 동작을 한다.
5. **Given** 방어·구르기·공중 점프·복귀기·던지기, **When** 쓰면, **Then** 각자의 동작이 보이고 그 길이는 조정표의 시간과 맞는다.

### User Story 3 - 휴대폰에서도 가볍게 돈다 (Priority: P1)

20명이 모인 채널에서도 휴대폰에서 첫 화면이 빨리 뜨고 움직임이 끊기지 않는다.

**Why this priority**: 운영자가 디자인 품질과 함께 성능을 "굉장히 중요하다"고 했다. 아름다워도 느리면 쓰지 않는다.

**Independent Test**: 성능 예산(FR-020~FR-027)의 항목마다 정한 측정 방법을 CI와 미리보기 배포에서 돌린다.

**Acceptance Scenarios**:

1. **Given** 채널 상한 20명이 모두 다른 모습인 방, **When** 휴대폰으로 들어가면, **Then** 001 SC-001(4G 10초)을 지키고 캐릭터 에셋 합계가 예산 안이다.
2. **Given** 같은 방, **When** 휴대폰에서 움직이면, **Then** 프레임 예산(FR-026)을 지킨다.
3. **Given** 멀리 있는 참가자, **When** 화면에 작게 보이면, **Then** 가벼운 모습(LOD)으로 바뀌어도 누구인지(색·실루엣) 알아볼 수 있다.

---

### User Story 4 - 2D 화면에서도 누가 누구인지 보인다 (Priority: P2)

2D 대체 화면을 쓰는 사람도 참가자 목록과 경기장 옆 그림에서 각 사람의 캐릭터를 같은 색과 얼굴 아이콘으로 알아본다.

**Why this priority**: 헌법 V(2D 대체 화면). 3D와 같은 사람을 같은 모습으로 알아봐야 대화·경기가 이어진다.

**Independent Test**: 2D 화면에서 참가자마다 아이콘과 대체 텍스트가 있는지 확인하고, 3D 화면과 같은 참가자의 모습 정보(색 이름)가 같은지 비교한다.

**Acceptance Scenarios**:

1. **Given** 2D 화면의 참가자 목록, **When** 보면, **Then** 닉네임 옆에 그 사람 캐릭터의 얼굴 아이콘이 있고, 스크린 리더는 "닉네임, 머리 색·옷 색" 같은 짧은 설명을 읽는다.
2. **Given** 2D 경기장 옆 그림, **When** 보면, **Then** 참가자 점이 그 사람 옷의 주 색으로 칠해진다.

### Edge Cases

- 같은 모습 조합이 두 사람에게 나올 때: 닉네임 이름표로 구분한다. 한 채널 안의 겹침은 FR-011이 줄인다.
- 기술 동작 중에 다른 동작이 들어올 때(잽 중 맞음 등): 맞는 동작이 이긴다. 우선순위는 FR-015.
- 동작 파일이나 모습 파일을 못 받았을 때: 기본 모습·기본 동작으로 보이고 방은 계속 쓸 수 있다.
- WebGL이 없거나 너무 느린 기기: 2D 화면으로 바뀌고(001), 캐릭터 3D 파일은 받지 않는다.
- 006 기술이 아직 없을 때: 006 자리(FR-014)는 비어 있고 다른 동작은 그대로 동작한다.
- 다크 모드·흔들림 끄기: 캐릭터 동작은 화면 흔들림 설정과 관계없이 나온다(흔들림은 카메라만).

## Requirements *(mandatory)*

### 스타일

- **FR-001**: 모든 캐릭터는 하나의 스타일 가이드([style-guide.md](style-guide.md))를 따른다. 가이드는 머리 수 비율, 키, 실루엣 규칙,
  팔레트(피부·머리·옷 색 목록과 값), 재질(광택, 그림자 받는 방식), 외곽선 여부와 두께, 얼굴 구성(눈·볼·입), 손발 모양을 값으로 정한다.
- **FR-002**: 스타일 방향은 운영자가 서로 다른 시안 3종(실제 방 화면에 넣어 찍은 것)을 보고 고른다. 고른 방향만 가이드에 남긴다.
- **FR-003**: 가이드는 003의 디자인 기준과 맞는다. 아바타 얼굴이 검게 뭉개지지 않고(003 SC-002) 테마 조명 아래에서 옷 색이 서로 구분된다.
  외곽선을 쓰는 방향을 고르면 003 FR-014와 맵 작업의 기준도 같은 PR에서 바꾼다.
- **FR-004**: 캐릭터는 특정 기존 작품의 캐릭터·화풍을 흉내 내지 않는다(헌법). 가이드는 이 서비스만의 표지(예: 고유한 머리·몸 비율, 손 모양, 색 조합)를 하나 이상 정한다.
- **FR-005**: 캐릭터 파일은 모두 저장소의 생성 스크립트 한 곳에서 만든다(도구 버전 고정). 스크립트를 다시 돌리면 정점·삼각형·뼈·동작 수와 모양이 같은 파일이 나오고
  (바이트까지 같지 않아도 된다), `CREDITS.md`에 스크립트와 명령을 적는다.

### 모습 (커스터마이즈)

- **FR-010**: 사람마다 모습은 지금처럼 기기 키에서 정해진다(이용자가 고르지 않는다, 001 research R7). 모습은 부위 조합이다:
  피부색, 머리 모양, 머리 색, 윗옷 모양, 윗옷 색, 아래옷 색, 신발 색. 초기 수: 피부 6, 머리 모양 5, 머리 색 7, 윗옷 모양 3, 윗옷 색 8, 아래옷 색 5, 신발 색 4.
- **FR-011**: 20명 채널에서 모든 부위가 같은 두 사람이 나올 확률이 1% 이하, 5명 방에서 머리 모양·머리 색·윗옷 색이 모두 같은 두 사람이 나올 확률이 5% 이하가 되도록 조합 수를 둔다
  (FR-010의 초기 수로 각각 약 0.2%, 3.5%). 같은 모습은 이름표로 구분한다.
- **FR-012**: 모습은 서버가 정해 다른 참가자에게 보낸다(지금 `avatarId`처럼). 모습 정보는 기기 키에서 계산한 값이라 개인정보가 아니다(헌법 II).
  모습 목록·값은 모습 목록(004 FR-030a의 LOOKS와 같은 방식) 한 곳에서 정한다.

### 동작 (애니메이션)

- **FR-013**: 동작 목록과 단계는 아래 표다. 모든 캐릭터가 같은 뼈대를 써서 동작을 한 벌만 둔다. 기술 동작은 선딜(준비)·활성(맞는 순간)·후딜(돌아옴) 자세를 가진다.

| 묶음 | 동작 | 단계와 길이 |
|---|---|---|
| 이동 | 서 있기, 걷기, 달리기 | 반복 |
| 이동 | 점프(뛰기·공중·착지), 공중 점프, 복귀기 | 뛰기 0.1초, 공중 반복, 착지 0.15초. 공중 점프·복귀기는 한 번 |
| 004 공격 | 잽 1타·2타·3타 | 선딜 0(누른 순간이 활성), 활성은 타격 정지 동안 유지, 후딜은 다시 쓰기 시간(조정표) |
| 004 공격 | 강펀치 모으기·놓기 | 선딜은 모으는 동안(모은 비율만큼 깊어짐), 놓기 활성은 타격 정지 동안, 후딜은 다시 쓰기 시간 |
| 004 공격 | 던지기 | 붙잡기·던지기가 한 동작. 활성은 누른 순간, 후딜은 다시 쓰기 시간 |
| 004 방어 | 방어(누르는 동안), 구르기 | 방어 시작 0.08초 뒤 유지, 구르기는 무적 시간과 같은 길이 |
| 004 맞기 | 움찔(약·강), 날아가기, 벽 낙법, 넉아웃 낙하, 다시 서기 | 움찔은 경직 시간, 날아가기는 비행 동안 반복, 다시 서기는 다시 시작 순간 0.4초 |
| 004 건설 | 블록 놓기, 블록 치기 | 0.25초, 블록 치기는 잽 1타 자세를 쓴다 |
| 006 | 006 스펙의 기술 목록 | 006이 정한 기술마다 같은 세 단계. 006 스펙이 머지되면 이 표에 행을 더한다 |

- **FR-014**: 기술 동작의 단계 길이는 조정표(004 FR-030, 006의 표)에서 읽는다. 조정표를 바꾸면 동작 길이도 함께 바뀌고 동작 파일은 다시 만들지 않는다.
  동작은 판정 시각을 늦추거나 당기지 않는다. 판정에 선딜이 생기면(006 등) 그 시간을 선딜 자세 길이로 쓴다.
- **FR-015**: 동작 우선순위: 넉아웃 > 날아가기 > 움찔 > 낙법 > 구르기 > 공격 > 방어 > 점프 > 이동. 높은 것이 들어오면 낮은 것을 끊는다. 전환은 0.1초 안에 섞는다(맞는 동작은 섞지 않고 바로 바꾼다).
- **FR-016**: 다른 참가자의 기술 동작도 그 사람 화면과 같은 단계로 보인다. 공격·날아가기·착지·낙법·넉아웃·다시 서기는 004가 이미 보내는 사건
  (`swing`, `launch`, `landed`, `knocked_out`, `respawned`)으로 정한다. 지금 다른 사람에게 가지 않는 방어 켜기·끄기, 구르기, 강펀치 모으기 시작은
  서버가 같은 채널의 경기장 참가자에게 짧은 자세 메시지로 알린다(입력 한 번에 한 번, 004의 입력 제한 안).

### 성능 예산 (값은 모두 초기값, 측정 방법은 [plan.md](plan.md)의 "성능 측정")

- **FR-020** 파일 크기: 모습 하나(몸·머리·옷 부위를 합친 것)는 압축한 파일 기준 60KB 이하, 동작 한 벌(모든 동작)은 250KB 이하. 방에 20명이 모두 달라도 캐릭터 에셋 합계 1MB 이하.
- **FR-021** 삼각형: 가까운 모습(LOD0) 4,000개 이하, 먼 모습(LOD1) 1,200개 이하(외곽선을 쓰면 외곽선 몸체 포함).
- **FR-022** 텍스처: 쓰지 않거나 모든 캐릭터가 나눠 쓰는 팔레트 그림 1장(64×64 이하, 8KB 이하). KTX2·Basis는 텍스처 합계가 256KB를 넘을 때만 쓴다(변환기 내려받기 비용 때문).
- **FR-023** 뼈: 캐릭터당 24개 이하. 얼굴 표정은 뼈 대신 눈·입 부위를 바꿔 낸다.
- **FR-024** 그리기 호출: 캐릭터 하나에 가까울 때 2번 이하(외곽선 포함), 멀 때 1번. 20명이 있는 채널에서 장면 전체 150번 이하.
- **FR-025** 첫 로드: 001 SC-001(Fast 4G에서 목록 → 방 → 첫 이동 10초 이내, 판례 2026-11-09-perf-4g)을 20명 방에서도 지킨다. 내 모습과 동작 한 벌을 먼저 받고 다른 사람 모습은 그 뒤에 받는다.
- **FR-026** 프레임: 20명 채널에서 저사양 휴대폰 기준(아래) 평균 30fps 이상, 1% 낮은 프레임 20fps 이상. 자동 측정은 CPU 4배 느리게 한 모바일 에뮬레이션에서 캐릭터 갱신(동작·뼈)에 쓰는 시간이 프레임당 4ms 이하.
  저사양 기준기기는 2021년 보급형 안드로이드(예: Galaxy A12급, Chrome 최신)다. 실기기 측정은 미리보기 배포에서 한다.
- **FR-027** LOD: 카메라에서 12m보다 먼 캐릭터는 LOD1로, 25m보다 먼 캐릭터는 동작을 초당 15번만 갱신한다. 화면에 캐릭터가 12명을 넘으면 저사양 모드(굵은 포인터)에서 거리를 8m로 줄인다.
  LOD1은 실루엣·주 색이 LOD0과 같아 누구인지 알아볼 수 있다.

### 2D 대체 화면

- **FR-030**: 2D 화면의 참가자 목록은 사람마다 그 모습의 얼굴 아이콘(생성 스크립트가 함께 만든 작은 그림)과 짧은 대체 텍스트(머리 색·옷 색)를 보여 준다.
- **FR-031**: 2D 경기장 옆 그림의 참가자 점은 그 사람 윗옷 색이다. 글자·대비는 003 기준을 지킨다(점 옆의 % 숫자 색은 004 그대로).
- **FR-032**: 2D 화면은 캐릭터 3D 파일을 받지 않는다. 얼굴 아이콘 합계는 2D 첫 로드에 30KB 이하로 더한다.

### 그 밖

- **FR-040**: 운영자가 판정할 기준 화면(테마 3개 × 5명 방 첫 화면, 기술 동작 7종의 활성 자세, 20명 장면)을 자동으로 만들어 PR마다 결과물로 남긴다(003 FR-013 방식).
- **FR-041**: 화면 문구(대체 텍스트의 색 이름 등)는 i18n 키로 둔다(헌법).
- **FR-042**: 지금 캐릭터 파일 8개와 그 출처 행, 피부색 바꾸기 코드는 새 캐릭터가 들어오면 지운다.

### Key Entities

- **모습(Look)**: 기기 키에서 정한 부위 조합(FR-010). 피부·머리 모양·머리 색·윗옷 모양·윗옷 색·아래옷 색·신발 색의 번호.
- **부위(Part)**: 몸, 머리 모양, 윗옷 모양 같은 모델 조각. 모두 같은 뼈대에 붙는다.
- **팔레트(Palette)**: 스타일 가이드가 정한 색 목록. 모습의 색 번호가 가리킨다.
- **동작(Clip)**: FR-013 표의 한 행. 이름, 반복 여부, 단계(선딜·활성·후딜)와 각 단계 길이를 정하는 조정표 항목.
- **성능 예산(Budget)**: FR-020~FR-027의 상한 값. 측정 스크립트가 읽어 넘으면 실패시킨다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 운영자가 시안 3종 중 하나를 고르고, 완성한 캐릭터의 기준 화면(FR-040)을 보고 "아쉽지 않다"고 판정한다.
- **SC-002**: 5명 방 기준 화면에서 운영자가 다섯 사람을 모습만으로(이름표를 가리고) 서로 구별한다.
- **SC-003**: 성능 예산 FR-020~FR-024는 CI가 모든 캐릭터 파일에 대해 자동으로 확인하고, 넘으면 PR이 실패한다.
- **SC-004**: 20명 방에서 001 SC-001(4G 10초)을 지킨다.
- **SC-005**: 저사양 기준기기 실측에서 20명 장면 평균 30fps 이상(FR-026). 실기기가 없으면 자동 측정값과 운영자 휴대폰 미리보기로 대신하고 그 사실을 tasks.md에 적는다.
- **SC-006**: 기술 동작 7종(잽 3타, 강펀치, 던지기, 방어, 구르기, 움찔, 날아가기)의 활성 자세를 운영자가 기준 화면에서 기술 이름만 보고 맞힌다.
- **SC-007**: 2D 화면의 a11y 검사(001 SC-007)가 계속 통과하고, 참가자마다 아이콘 대체 텍스트가 있다.

## Assumptions

- 생성 도구는 헤드리스 Blender(Python, 클라우드 세션과 CI에서 설치)다. 돈을 쓰는 도구·서비스는 쓰지 않는다(판례 2026-11-27-own-assets).
- 뼈대·동작은 모든 모습이 함께 쓴다. 체형(004 범위 밖 "체형 3종")은 005에서 만들지 않지만 뼈대는 비율을 바꿀 수 있게 둔다.
- 006(스킬·콤보) 스펙은 다른 세션이 쓰는 중이다. 006이 머지되면 FR-013 표에 006 행을 더하는 스펙 PR을 낸다.
- 키는 001처럼 약 1.65m가 아니라 스타일 가이드가 정한다. 가구·문·경기장 블록(1m)과의 비율은 맵 작업과 가이드로 맞춘다.
