# 화면정의서 v1

헌법의 산출물 "화면정의서(spec + 디자인 시안)" 중 글 부분이다. **Claude Design 시안은 아직 없다**(다음 단계에서 이 문서를 입력으로 만든다).
모든 문구는 i18n 키로 넣는다(여기 적힌 한국어는 `ko.ts`의 초안). 폭 기준: 모바일 360px, 데스크톱 1280px.

## 화면 목록과 경로

| ID | 화면 | 경로 | 스토리 |
|---|---|---|---|
| S1 | 방 목록 | `/` | US1, US3 |
| S2 | 방 만들기 | `/new` | US3 |
| S3 | 방 (3D / 2D) | `/rooms/:id` | US1, US2, US4, US5 |
| S4 | 방 수정·삭제 | `/rooms/:id/edit` | US6 |
| S5 | 관리자 | `/admin` | US7 |
| S6 | 없는 방 / 삭제된 방 | `/rooms/:id` (404·410일 때) | Edge Cases |

## 공통 상태

| 상태 | 표시 |
|---|---|
| 로딩 | 스켈레톤(목록) 또는 진행 표시 + "불러오는 중" |
| 오류(네트워크) | "연결에 문제가 있어요" + 다시 시도 버튼 |
| 요청 횟수 초과(429) | "잠시 후 다시 시도해 주세요 (N초)" — `retryAfterMs` 사용 |
| 다시 연결 중(S3) | 상단 띠 "다시 연결 중…", 이동·채팅 입력 비활성 |

## S1. 방 목록

- 머리글: 서비스 이름, "방 만들기" 버튼(→ S2).
- 목록 항목(최신순): 제목, 테마 이름, 현재 인원("지금 N명"), 만든 시각(상대 시간). 항목 전체가 S3 링크.
- 아래로 스크롤하면 다음 페이지를 불러온다(`nextCursor`). 키보드 사용자를 위해 "더 보기" 버튼도 둔다.
- 빈 상태: "아직 방이 없어요" + "첫 방 만들기" 버튼.
- 모바일: 한 줄 카드 목록. 데스크톱: 2~3열 카드.

## S2. 방 만들기

- 입력: 제목(필수, 60자, 남은 글자 수), 설명(선택, 300자), 테마(카드 3개 중 하나, 미리보기 이미지), 글 비밀번호(필수, 4~64자,
  "수정·삭제할 때 필요해요. 잊으면 찾을 수 없어요" 안내), Turnstile 위젯.
- 제출 버튼은 필수 입력과 Turnstile이 채워질 때까지 비활성.
- 제출하면 먼저 서버와 같은 스키마(`src/core/api-schemas.ts` `createRoomRequest`)로 검사하고, 틀리면 요청 없이 필드 아래에 오류 문구를 보인다.
- 400: 필드 아래에 오류 문구(`fields`의 문구 키). 403(Turnstile)·그 밖의 실패: 위젯을 다시 받고 다시 시도 안내. 429: 공통 상태.
- 성공: S3로 이동.

## S3. 방

### 공통 영역 (3D·2D 같음)

- 머리글: 방 제목, 채널 번호("채널 2"), 인원("12/20"), 3D↔2D 전환 버튼, 메뉴(방 신고, 방 수정·삭제 → S4, 목록으로).
- 내 닉네임 표시.
- 채팅 패널: 메시지 목록(닉네임 + 내용, 최근 100개), 입력창(200자), 보내기. 각 메시지에 "신고" 동작. 너무 빠르면 "잠시 후 다시 시도해 주세요"를 기다리는 동안 보이고, 걸린 메시지는 입력창에 돌아와 기다린 뒤 다시 보낼 수 있다(그동안 보내기는 막힌다) (판례 2026-11-09-chat-panel).
- 방 정보: 설명(접기/펼치기).

### 3D 화면

- 전체 화면 캔버스, 3인칭 카메라.
- PC: WASD/방향키 이동, Shift 달리기, Space 점프, 마우스 드래그 카메라 회전. Enter로 채팅 입력 포커스, Esc로 해제
  (채팅 입력 중에는 이동 키가 글자로 들어간다).
- 모바일: 왼쪽 아래 조이스틱(`ecctrl/input`), 오른쪽 아래 점프 버튼, 오른쪽 화면 드래그로 카메라 회전. 채팅은 접힌 아이콘 → 탭하면
  아래에서 올라오는 패널.
- 다른 참가자 머리 위에 닉네임.
- 3D 리소스 로딩 중: 진행률 표시. 실패하면 2D로 전환하고 "3D를 불러오지 못해 텍스트 화면으로 보여드려요" 안내.

### 2D 화면 (시맨틱 HTML)

- `<main>` 안에 `<h1>` 방 제목, 설명, 테마 이름, 채널.
- 참가자 목록 `<ul>`: 닉네임, 상태(가만히/걷는 중/달리는 중/점프), 대략 위치("입구 근처" 같은 테마 구역 이름).
- 채팅 `<section>`의 메시지 목록이 `aria-live="polite"`: 새 메시지를 스크린 리더가 읽는다.
- 입장·퇴장 알림도 `aria-live`로 읽는다.
- 키보드만으로 채팅 입력, 메시지 신고, 방 신고, 3D 전환이 가능해야 한다.
- WebGL이 없으면 2D만 보여주고 3D 전환 버튼은 없다. `rb.view`는 전환 버튼을 눌렀을 때만 저장한다(자동 2D·3D 실패는 저장하지 않음, 판례 2026-11-07-2d-view-rules).

### 3D 동작 ↔ 2D 요소 대응

| 3D 동작 | 2D 요소 |
|---|---|
| 방에 들어가 아바타로 나타남 | 참가자 목록에 "나" 항목 |
| 다른 아바타가 보임·움직임 | 참가자 목록 항목과 상태·구역 갱신 |
| 아바타가 사라짐 | 목록에서 제거 + 퇴장 알림 |
| 머리 위 닉네임 | 목록의 닉네임 |
| 채팅 패널 | 같은 채팅 섹션(공유 컴포넌트) |
| 메뉴의 방 신고 | 같은 메뉴(공유 컴포넌트) |
| 이동 | 2D에서는 이동하지 않는다(위치는 마지막 위치 또는 스폰 지점에 머문다) |

### 신고 대화상자 (방·메시지 공통)

- 사유 라디오(스팸, 욕설·괴롭힘, 성적인 내용, 불법, 기타), 보내기.
- 결과: "신고가 접수됐어요" / 중복: "이미 신고했어요" / 메시지 서명 만료: "오래된 메시지는 신고할 수 없어요".

### 방이 삭제됨 (`room_deleted`)

- 모달 "이 방은 삭제됐어요" + 확인 → S1.

## S4. 방 수정·삭제

- 입력: 제목, 설명, 테마(현재 값 채움), 글 비밀번호(필수).
- 테마를 바꾸면 "방 꾸밈이 새 테마 기본값으로 바뀌어요" 안내.
- 저장 → S3. 삭제는 확인 대화상자("삭제하면 되돌릴 수 없어요") 후 → S1.
- 403: "비밀번호가 맞지 않아요". 429: 공통 상태.

## S5. 관리자

- 처음에는 토큰 입력 화면만. 토큰은 탭 메모리(sessionStorage)에만 둔다.
- 401: "토큰이 맞지 않아요". 429: 공통 상태.
- 신고 목록(열린 것 / 처리된 것 탭): 대상 종류, 방 제목(링크), 메시지 스냅샷(닉네임·내용·시각·채널), 사유, 신고 수, 신고 시각.
- 동작: "방 삭제"(확인 후), "처리 완료".
- 모바일에서도 쓸 수 있되 레이아웃은 단순 목록.

## S6. 없는 방 / 삭제된 방

- 404: "없는 방이에요" + 목록으로 버튼. 410: "삭제된 방이에요" + 목록으로 버튼.
- 서버도 같은 상태 코드로 HTML을 돌려준다(검색 엔진이 색인하지 않도록).
