# welcome 전에 닫히면 방을 조회하고, 테마가 바뀌면 서버도 모두를 스폰으로 옮긴다

- 날짜: 2026-11-09
- 대상: specs/001-realtime-room-board/contracts/websocket.md(닫힘 코드 표 아래, `room_updated`), tasks.md T082·T083·T085
- 출처: 001 US6 PR (T079~T085), PR #21 리뷰 제안
- 대체한 판례: 없음

## 결정

- 클라이언트는 `welcome`을 받기 전에 닫힌 연결(닫힘 코드가 재연결 대상일 때)마다 다시 연결하기 전에
  `GET /api/rooms/{roomId}`를 부른다. 404·410이면 재연결하지 않고 `4001`과 같은 "이 방은 삭제됐어요" 안내를 보인다.
  조회가 실패하면(네트워크) 평소처럼 백오프 재연결한다.
- `room_updated`로 테마가 바뀌면 서버(`RoomSession.update`)도 모든 참가자의 자세를 새 스폰으로 바꾸고 소켓 attachment에 다시 쓴다.
  테마가 바뀌었는지는 Worker가 D1의 이전 값과 비교해 DO에 알린다.
- 방 삭제 알림(`room_deleted` 후 4001)은 세션을 거치지 않고 DO가 연 소켓 전부에 보낸다. 그 DO는 이후 세션을 다시 만들지 않는다.

## 이유

- 삭제된 방은 업그레이드를 410으로 거부하는데 브라우저는 이것을 `1006`으로만 알려서, 재연결 대기 중에 방이 지워지면 끝없이 재연결했다.
  "몇 번 실패하면"보다 "welcome 전에 닫히면 매번"이 세는 상태가 없고, 백오프가 있어 요청 수도 작다.
- 서버가 옛 자세를 두면 클라이언트가 새 스폰에서 보낸 첫 이동이 속도 검사에 걸려 옛 위치로 `correction`된다.
- Hibernation 뒤 깨어난 DO는 D1에서 이미 바뀐 방을 읽으므로, 세션 안에서 이전 테마와 비교할 수 없다. 깨어난 세션은 D1의 410 때문에
  아무도 모르므로 삭제 알림은 소켓 목록에서 직접 보낸다.

## 검토한 대안

- 연속 N번 실패 뒤에만 조회: 셀 상태가 생기고 그동안 사용자는 "다시 연결 중"만 본다.
- 테마가 바뀌면 서버가 모두에게 `correction`을 보냄: 클라이언트가 `room_updated`만으로 같은 일을 할 수 있어 메시지가 하나 더 늘 뿐이다.
