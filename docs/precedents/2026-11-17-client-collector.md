# 클라이언트 오류 수집기: 탭당 분당 10건, Error가 아닌 값은 버림, 화면 종류 매핑

- 날짜: 2026-11-17
- 대상: specs/002-auto-bugfix-loop research R4, tasks T037, `src/client/bug/collector.ts`, `src/core/fingerprint.ts`
- 출처: T037 PR(세션 판단, 운영자가 숫자를 바꿀 수 있음)
- 대체한 판례: 없음

## 결정

- 탭마다 분당 10건까지 보낸다(`RateBucket`). Worker의 IP당 한도와 같은 수다.
- 수집 경로: window `error`(경계 밖 렌더 오류 포함, React 19 기본 동작), `createRoot`의 `onCaughtError`(경계가 잡은 오류), `unhandledrejection`.
  루트 오류 경계는 새로 만들지 않는다.
- `Error`가 아닌 값(교차 출처 `Script error.`, 문자열 거부)은 보내지 않는다.
- 클라이언트도 가림 다음에 스키마 길이로 자르고 `file`은 파일 이름만 보낸다. UTF-8 4KB를 넘으면 뒤쪽 프레임부터 뺀다.
- `view`: 방 화면은 그때의 `3d`/`2d`, `/admin`은 `admin`, 그 밖(목록·만들기·수정·없는 주소)은 `board`.
- 스택 파서(V8, Firefox·Safari 형식)와 파일 이름 자르기는 core로 옮겨 Worker 서버 오류 기록과 같이 쓴다.

## 이유

- Worker는 스키마에 맞지 않거나 4KB를 넘는 리포트를 조용히 버린다. 클라이언트가 맞춰 보내야 리포트가 사라지지 않는다.
- 같은 오류가 렌더마다 반복되면 한 탭이 IP 한도를 다 쓴다. 서버와 같은 수면 정상 탭이 더 보낼 일은 없다.
- 스택이 없는 값은 지문이 오류 이름 하나로 뭉치고 소스 위치로 해석되지 않아(FR-015) 쓸모가 없다.
- 루트 경계를 두면 대체 화면을 새로 정해야 한다(스펙에 없음).

## 검토한 대안

- Error가 아닌 값도 `String()`으로 보내기: 지문이 뭉치고 문자열에 사용자 콘텐츠가 실릴 수 있다. 기각.
- 방 화면의 화면 종류를 DOM 속성에서 읽기: 화면 구조에 묶인다. RoomPage가 수집기에 알려 준다.
