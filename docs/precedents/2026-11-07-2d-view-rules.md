# 2D 화면 전환 규칙과 대략 위치

- 날짜: 2026-11-07
- 대상: specs/001-realtime-room-board/contracts/screens.md S3, data-model.md Theme, tasks.md T053~T056
- 출처: 001 US2 PR (T051~T057)
- 대체한 판례: 없음

## 결정

- WebGL이 없으면 `rb.view`와 상관없이 2D이고, 3D 전환 버튼을 보이지 않는다. 눌러도 3D를 그릴 수 없기 때문이다.
- `rb.view`는 사용자가 전환 버튼을 눌렀을 때만 저장한다. 자동 2D(WebGL 없음)와 3D 로딩 실패 뒤의 2D는 저장하지 않는다.
  한 방에서 3D가 실패해도 다른 방은 다시 3D로 시도한다.
- 2D의 대략 위치는 테마마다 바닥 사각형 구역 목록으로 정한다. 위치의 x·z가 들어가는 첫 구역 이름을 쓰고, 마지막 구역은 나머지 전부다.
- 입장·퇴장 알림은 `peer_joined`·`peer_left` 메시지에서만 만든다. 재연결 때 참가자 목록을 다시 받는 것은 알리지 않는다.

## 이유

FR-051 "언제든 전환"은 3D를 그릴 수 있는 환경에서 뜻이 있다. 실패한 시도를 저장하면 일시적인 오류 하나가 모든 방을 2D로 묶는다.
사각형 구역은 순수 함수 하나로 테스트할 수 있고 방 데이터 형식을 바꾸지 않는다.

## 검토한 대안

- WebGL이 없어도 3D 버튼을 두고 누르면 실패 안내: 매번 실패하는 버튼이다.
- 오브젝트에서 가장 가까운 것의 이름("카운터 근처"): 오브젝트가 바뀌면(꾸미기, v1 밖) 문구 키도 따라 바뀌어야 한다.
- 참가자 목록을 이전 목록과 비교해 알림: 재연결 때마다 모두 나갔다 들어온 것처럼 읽힌다.
