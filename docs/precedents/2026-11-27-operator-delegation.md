# 운영자 위임: 세션이 헌법·스펙·설정 변경과 배포까지 한다 (헌법 2.0.0)

- 날짜: 2026-11-27
- 대상: 헌법 원칙 VII(v2.0.0), specs/002-auto-bugfix-loop/spec.md FR-066, `scripts/merge-gate.mjs`, CLAUDE.md 머지 규칙
- 출처: 운영자 요청("너가 배포든 뭐든 다 권한을 가져", "헌법 수정 스펙 수정 등등 모두 권한을 줄게")
- 대체한 판례: 2026-11-09-session-auto-merge(허용 경로 제한), 2026-11-10-preview-no-branch-rule(배포마다 승인)

## 결정

- 운영자가 시킨 클라우드 세션의 PR은 바꾼 경로와 관계없이(헌법·스펙·에이전트 규칙·워크플로·스크립트·`package.json`·설정 포함)
  필수 검사(`ai-review` 포함)를 모두 통과하면 auto-merge로 머지된다. `merge-gate`는 `agent/` 브랜치만 실패시킨다.
- 미리보기(Environment `preview`)와 운영(Environment `production`) 배포는 운영자 승인 없이 세션이 실행한다. 운영 배포는 main에서만 돈다.
- 남는 경계: 이슈·리포트(외부 입력)에서 시작한 수정 에이전트 PR은 사람이 머지한다. 기본 브랜치 직접 push와 보호 규칙 우회는 하지 않는다.

## 이유

- 운영자 머지·승인 대기가 작업을 멈추게 했다(004 T055 미리보기 측정, 설정 PR). 운영자가 판단을 세션에 맡기기로 했다.
- 외부 입력이 에이전트를 조종하는 통로(헌법 VII 근거)는 세션 위임과 별개라 그대로 막는다.
- 승인 대신 PR 코드가 닿지 않는 곳에서 막는다(PR #103 리뷰: PR은 `preview.yml`을 고치거나 새 워크플로를 더할 수 있다).
  미리보기 워크플로는 `pull_request_target`(main의 정의, base ref로 실행)이고, Environment `preview`는 배포 브랜치를 `main`만 둔다.
  PR이 더한 워크플로는 `refs/pull/N/merge`로 돌아 거절된다. 믿을 수 있는 `if`가 이 저장소의 `claude/*`만 고르고,
  세션 브랜치 Ruleset이 수정 에이전트의 push를 `agent/**`로 묶어 `claude/*`는 운영자 계정(세션)만 만든다. 둘 중 하나라도 없애면 이 판례를 다시 본다.

## 받아들인 위험

- `claude/*` PR의 코드(`npm ci`·빌드)는 미리보기 비밀값 옆에서 돈다. 그 브랜치를 세션만 만들 수 있어 받아들인다.

- 세션이 규칙 자체(이 판례, `merge-gate`, 워크플로)를 바꿔 머지할 수 있다. 독립 리뷰 `ai-review`와 필수 검사가 유일한 확인이다.
  그런데 같은 저장소 PR의 `ai-review`·`ci`는 PR 안의 `pr-review.yml`·`.claude/skills/pr-review/`·`ci.yml`로 돈다(PR #103 리뷰).
  그래서 이 파일들을 바꾸는 세션 PR은 약해진 자기 검사로 머지될 수 있다. 운영자가 전부 위임을 골라 받아들이고, 세션은 이런 PR 본문에
  검사를 어떻게 바꿨는지 적는다. 막아야 하면 그 경로만 `merge-gate`에 되돌리거나 리뷰를 기본 브랜치 정의로 돌린다.
- 운영 배포의 잘못은 다음 배포로 되돌린다. 배포 뒤 운영 사이트를 확인한다(CLAUDE.md).

## 검토한 대안

- 미리보기만 위임, 운영 배포·규칙 변경은 사람: 운영자가 "모두"를 골라 기각.
- 수정 에이전트 PR까지 자동 머지: 외부 입력이 권한을 얻는 통로라 기각.
