# Turnstile 테스트 비밀 키는 siteverify를 부르지 않는다

- 날짜: 2026-11-08
- 대상: specs/001-realtime-room-board/tasks.md T063, research R9(봇 방지)
- 출처: 001 US3 서버 PR (#24)
- 대체한 판례: 없음

## 결정

- `verifyTurnstile`은 Cloudflare가 문서로 정한 테스트 비밀 키 두 개에 대해 문서의 답을 바로 돌려준다.
  `1x0000000000000000000000000000000AA`는 통과, `2x0000000000000000000000000000000AA`는 실패다. 네트워크는 쓰지 않는다.
- 그 밖의 비밀 키는 빈 값을 포함해 모두 siteverify에 묻는다. 운영 비밀 키는 늘 siteverify를 거친다.
- worker 테스트는 테스트 키가 아닌 비밀 키를 바인딩하고 siteverify를 가짜 응답으로 바꾼다. 그래야 "400·429는 siteverify를 부르지 않는다"는 검사가 뜻을 가진다.

## 이유

클라우드 세션의 workerd(로컬 dev, vitest)는 DNS가 없어 siteverify에 닿지 못한다. 그래서 로컬 E2E에서 방 만들기가 500이 됐다.
테스트 키의 답은 Cloudflare가 고정한 값이라, 미리 돌려줘도 결과가 같다. 이 분기로는 실패해야 할 요청이 통과하지 못한다.
진짜 siteverify 요청 형식(`secret`, `response`, `remoteip` 없음)은 가짜 응답 테스트로 확인한다. 실제 응답 형식은 curl로 확인했다
(2026-11-08, 테스트 키 두 개). 그 뒤로 자동 검사 중 실제 siteverify를 부르는 것은 없다.

## 검토한 대안

- E2E에서만 방 만들기를 건너뜀: 사용자가 방을 만드는 흐름(Q6)을 로컬에서 확인할 수 없다.
- dev 전용 환경 변수로 Turnstile을 끔: 끄는 스위치가 운영에 새어 나갈 수 있다. 테스트 키는 운영에서 써도 결과가 같다.
