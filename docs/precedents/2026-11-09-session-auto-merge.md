# 세션 PR은 독립 리뷰를 포함한 필수 검사를 통과하면 auto-merge

- 날짜: 2026-11-09
- 대상: 헌법 원칙 VII(v1.2.0), specs/002-auto-bugfix-loop/spec.md FR-066, quickstart 기본 브랜치 보호
- 출처: 운영자 요청("리뷰는 진행하고 알아서 머지하게 하고 싶어")
- 대체한 판례: 2026-11-06-constitution-v1-1, 2026-11-06-independent-pr-review (둘 다 "머지는 사람" 부분만)

## 결정

운영자가 시킨 클라우드 세션이 연 PR은 바꾼 파일이 모두 허용 경로(서비스 코드·테스트·문서)에 있고 필수 검사가 모두 통과하면 세션이 auto-merge를 걸어
머지되게 한다. 기본 브랜치 보호는 승인 1명 대신 이 필수 검사로 막는다. 이슈·리포트에서 시작한 수정 에이전트 PR, 그리고
허용 경로 밖(헌법, 에이전트 규칙, 워크플로, 스크립트, `package.json`, 설정)을 바꾸는 PR은 계속 사람이 머지한다. 이 구분은 문서가 아니라
필수 검사 `merge-gate`가 강제한다: 그런 PR에서 실패하므로 운영자의 관리자 우회로만 머지된다. `merge-gate`는
`pull_request_target`으로 기본 브랜치의 정의를 실행해, PR이 자기 검사를 고쳐 통과하지 못하게 한다.

## 이유

PR 작성자가 운영자 계정이라 스스로 승인할 수 없어, 지금까지는 매번 관리자 우회로 사람이 머지했다. 독립 리뷰(`ai-review`)가
PR #8·#13에서 실제 결함을 잡는 것을 확인했으므로(T048) 리뷰 품질을 본 뒤 다시 판단하기로 한 조건이 채워졌다. 외부 입력에서
시작한 PR과 규칙 자체를 바꾸는 PR은 에이전트가 자기 권한을 넓히는 통로가 될 수 있어 제외한다.

## 받아들인 위험

`tests/`·`src/`를 고쳐 테스트를 약하게 만드는 세션 PR은 경로로 가를 수 없다. 이는 독립 리뷰 `ai-review`와 헌법 III(테스트
비활성화 금지)이 맡는다. 운영자가 이 수준의 신뢰를 고른 것이다.

## 검토한 대안

모든 PR 자동 머지(외부 입력이 리뷰만 통과하면 들어가서 기각). 세션이 관리자 우회로 직접 머지(보호 규칙이 검사를 강제하지
못해 기각). CODEOWNERS 코드 오너 리뷰(`agent/` 브랜치를 못 가려 기각). 사람이 머지할 경로의 차단 목록(리뷰 네 라운드 동안 매번 빠진
설정 파일이 나와, 기본값이 사람인 허용 목록으로 바꿈). 지금처럼 운영자가 "머지해"라고 말할 때만(운영자 요청과 달라 기각).
