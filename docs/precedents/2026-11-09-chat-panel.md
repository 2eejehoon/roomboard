# 채팅 패널: 읽어 주는 영역은 메시지 목록, 최근 100개만 둔다

- 날짜: 2026-11-09
- 대상: specs/001-realtime-room-board/contracts/screens.md S3(채팅 패널, 2D 채팅), tasks.md T073
- 출처: 001 US4 PR (T068~T074)
- 대체한 판례: 없음

## 결정

- 2D에서 `aria-live="polite"`는 채팅 `<section>` 전체가 아니라 그 안의 메시지 목록에 둔다.
- 화면은 받은 메시지를 최근 100개까지만 들고 있는다.
- 3D에서 채팅 패널은 `<details>`다. 터치 기기에서는 접힌 채로 시작하고, 키보드가 있는 기기에서는 펼친 채로 시작한다.

## 이유

- 섹션 전체가 읽어 주는 영역이면 입력창 옆 안내나 버튼 상태가 바뀔 때도 읽힌다. 새 메시지만 읽어야 한다.
- 서버는 채팅을 저장하지 않으니 오래 머문 탭의 메모리만 늘어난다. 100개면 스크롤로 되돌아볼 만큼은 된다.
- `<details>`는 스크립트 없이 접힘·펼침과 키보드 조작을 준다.

## 검토한 대안

- 개수 제한 없음: 긴 세션에서 목록과 메모리가 끝없이 늘어난다.
- 직접 만든 접힘 버튼: `<details>`와 같은 일을 코드로 다시 한다.
