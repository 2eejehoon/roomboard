# 버그 신고 화면: 방 머리 영역 버튼, 최근 지문은 클라이언트가 계산, 이슈화 E2E는 응답을 대신함

- 날짜: 2026-11-17
- 대상: specs/002-auto-bugfix-loop FR-004·FR-014, US3, research R4·R9, tasks T040·T042
- 출처: T040·T042 PR(세션 판단, 운영자가 바꿀 수 있음)
- 대체한 판례: 없음

## 결정

- "버그 신고" 버튼은 3D·2D가 같이 쓰는 방 머리 영역(방 신고 옆)에 둔다. 목록·만들기 화면에는 두지 않는다(FR-004는 3D·2D 화면).
- 신고 `context.recentFingerprints`: 수집기가 실제로 보낸 오류 리포트의 지문을 core `fingerprint()`로 계산해 서로 다른 최근 5개를 둔다.
  배포 빌드의 청크에서 난 오류면 Worker가 계산하는 지문과 같다(Worker가 그 파일 이름을 그대로 두고, 클라이언트가 이미 가리고 잘랐으므로).
- 관리자 화면 "버그 신고" 탭은 신고마다 이슈 제목·공개 요약 입력과 "이슈로 만들기"·"버리기"를 둔다. 동작은 한 번에 하나(중복 이슈 방지).
- E2E는 이슈화 요청에 브라우저에서 201을 대신 답한다. 로컬·CI에는 실제 GitHub 토큰이 없고, Worker 쪽 이슈화는 Worker 테스트가 검증한다.

## 이유

- 머리 영역은 3D·2D 모두에 있어 한 곳으로 헌법 V를 지킨다.
- Worker가 지문을 202 응답에 돌려주면 수집 여부가 드러난다(R4는 항상 202로 아무것도 알려주지 않는다).

## 검토한 대안

- 지문 없이 보내기: 스펙(US3)이 최근 오류 지문을 요구한다. 기각.
- 클라이언트가 `/manifest.json`을 읽어 Worker와 똑같이 맞추기: 요청이 하나 늘고, 빌드 밖 파일은 원래 이슈가 되지 않는다. 기각.
