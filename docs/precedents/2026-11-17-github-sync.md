# GitHub 동기화: 목록 한 번으로 닫힘·상한·토큰 만료, 늦은 gated 라벨, 토큰 알림은 만료일로 한 번

- 날짜: 2026-11-17
- 대상: specs/002-auto-bugfix-loop contracts/github.md(자동 이슈 형식, `[ops]`), data-model `token_alerts`, research R3, tasks T033·T036
- 출처: T033·T036 남은 것 PR(세션 판단)
- 대체한 판례: 없음

## 결정

- Cron은 `source:service` 열린 이슈 목록을 한 번 읽는다. 그 수가 열린 이슈 상한(20)이고, 목록에 없는 `open` 지문은 `closed`로 두며
  `fixed_version`은 그때의 배포 버전이다. 같은 응답의 `github-authentication-token-expiration` 헤더가 PAT 만료일이다.
- 클라이언트 지문은 이슈를 먼저 만들고(1건), 나중에 `gated`가 되면 본문 갱신 때 `agent:gated`를 더한다.
- PAT 만료 알림은 알린 만료일을 `token_alerts`에 남겨 PAT 하나에 한 번만 연다.
- 이슈 본문의 DB 문자열은 모두 코드 스팬에 넣고 백틱·줄바꿈을 바꾼다.
- 하루 새 이슈 자리는 생성 전에 조건부 upsert로 잡는다(생성이 실패하면 그 자리는 버린다).
- 동기화 실패는 로그만 남기고 서버 오류로 기록하지 않는다. DO의 `webSocketMessage`·`webSocketClose`·`webSocketError`·`alarm`이 던진 예외는 기록한 뒤 다시 던진다.

## 이유

- 이슈마다 상태를 묻으면 5분마다 열린 이슈 수만큼 요청이 든다. 목록 하나면 한 번이고, 만료일도 운영자가 따로 넣을 필요가 없다.
- 이슈 생성 시점에 `gated`를 기다리면 SC-001(5분 안에 이슈)을 못 지킨다. 라벨을 나중에 더하지 않으면 클라이언트 이슈는 에이전트에 닿지 않는다.
- 만료 30일 전부터 매 Cron이 판단하므로 한 번만 열 표시가 필요하다. 새 PAT는 만료일이 달라 다시 알린다.
- 위조한 오류 이름이 코드 스팬을 깨면 공개 이슈에 멘션·마크다운이 들어간다.
- 생성 뒤에 세면 동시 실행이나 D1 실패에 상한을 넘을 수 있다. 상한은 넘지 않는 쪽이 안전하다.
- GitHub가 내려가면 그 오류가 지문이 되고, 그 지문의 이슈를 만들다 다시 실패한다(spec Edge Cases의 반복).
- fetch와 RPC의 예외는 Worker 경로의 `onError`가 이미 기록한다. 감싸면 두 번 센다.

## 검토한 대안

- 만료 알림을 열린 이슈 제목으로 중복 확인: 운영자가 갱신 없이 닫으면 5분마다 다시 연다. 검색은 색인이 늦다(판례 2026-11-13-intake-limit-alert). 기각.
- 이슈마다 `GET /issues/{n}`로 닫힘 확인: 위 이유로 기각.
- `gated`가 될 때까지 클라이언트 이슈를 만들지 않기: 위 이유로 기각.
