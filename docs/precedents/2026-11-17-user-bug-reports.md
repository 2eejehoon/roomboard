# 사용자 버그 신고: 식별자만 가림, 신고 한도 공유, 30일 삭제는 5분 Cron

- 날짜: 2026-11-17
- 대상: specs/002-auto-bugfix-loop FR-004·FR-014, research R4·R9, contracts/openapi.yaml(`/bug-reports/user`, `/admin/bug-reports*`), tasks T039·T041
- 출처: T039·T041 PR(세션 판단, 운영자가 바꿀 수 있음)
- 대체한 판례: 없음

## 결정

- 신고 원문과 운영자 제목·요약은 식별자 패턴(이메일·전화번호·IP·UUID·긴 토큰)만 가린다(`redactIds`). 오류 리포트의 따옴표 안 문자열 가림은 쓰지 않는다.
  가림 다음에 자른다(가림 표시가 더 길어 D1 길이 CHECK를 넘을 수 있으므로).
- 요청 횟수 제한은 콘텐츠 신고와 같은 `RL_REPORT`(IP당 분당 10건)를 쓴다. 순서는 한도 → 입력 검사(400) → Turnstile(403) → 저장(201).
- `context.themeId`는 테마 id 목록만, `context.appVersion`은 수집 경로와 같은 형식만 받고 아니면 `unknown`으로 저장한다(관리자 화면에 자유 문자열이 남지 않게).
- 30일 지난 신고 삭제는 기존 5분 Cron에서 GitHub 동기화와 따로 돌린다(토큰이 없는 미리보기에서도 지워지게).
- "이슈로 만들기"는 `source:user-report` 라벨로 운영자 제목·요약만 담은 이슈를 만들고, FR-013 자동 이슈 상한에 세지 않는다. `pending`인 신고만 이슈화·목록 대상이다.
  GitHub 실패는 502, 신고는 `pending`으로 남는다. 서버는 이슈화를 선점하지 않으므로 중복 클릭은 화면이 막는다.
- 관리자 목록은 최신 100건까지 보여 준다.

## 이유

- FR-014는 원문을 사용자 콘텐츠로 보고 식별자만 가리라고 한다. 따옴표 가림은 첫 따옴표부터 끝까지 지워 한국어 신고 문장을 못 쓰게 만든다.
- 새 한도 바인딩·Cron은 `wrangler.jsonc` 변경(운영자 머지 경로)이다. 신고 한도는 사람이 누르는 경로라 콘텐츠 신고와 같은 수가 맞다.
  자동 오류 한도(`RL_BUG_REPORT`)를 쓰면 오류가 쏟아지는 화면에서 그 오류를 신고할 수 없다.
- 운영자가 누르는 이슈화는 하루 몇 건이라 자동 이슈 상한(폭주 방지)과 목적이 다르다.

## 검토한 대안

- 신고 전용 한도 바인딩·매일 Cron 추가: 운영자 PR이 따로 필요하고 얻는 것이 없다. 보류.
- 목록 페이지 나눔: 계약에 커서가 없고 신고가 100건 넘게 쌓일 일이 드물다. 넘으면 그때 커서를 더한다.
