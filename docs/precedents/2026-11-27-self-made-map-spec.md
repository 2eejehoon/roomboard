# 007 자체 제작 맵 스펙: 성능 예산을 먼저, clarify 답은 세션이 정함

- 날짜: 2026-11-27
- 대상: specs/007-self-made-map/spec.md(범위, FR-001~FR-019, 성능 예산, Assumptions), research.md R1
- 출처: 운영자 결정(2026-11-27, "캐릭터를 먼저, 맵은 그다음(병렬 가능). 디자인 퀄리티와 성능이 굉장히 중요하다. 자체 제작으로 간다"), 007 스펙 PR
- 대체한 판례: 없음

## 결정

- 맵(방 인테리어·가구·경기장 블록·섬·배경·조명)을 저장소의 생성 스크립트(헤드리스 Blender Python, 코드 지오메트리, 절차적 텍스처)로 직접 만든다.
  무료 에셋 팩(KayKit 등), 생성 도구의 결과물, 유료 도구(Meshy 등)는 쓰지 않는다(운영자 확인, 부모 세션 전달). 제작은 005의 헌법 개정 머지 뒤, 스타일은 005 가이드.
- 성능 예산을 스펙 표로 먼저 정하고 기준선(main `4662ae7`)을 research R1에 남긴다. GPU 무관 항목은 PR마다 자동, 프레임은 미리보기 `?perf` 표시로 기준 기기에서.
- clarify 질문 5개는 운영자 위임(판례 2026-11-27-operator-delegation)으로 세션이 답을 정해 본문에 반영했다. 운영자가 다르게 답하면 새 판례로 바꾼다.
  1. 저사양 기준 기기와 목표: 2021년 보급형 안드로이드(갤럭시 A12·A13급) 30fps(p95 33ms), PC 내장 GPU 60fps. 기기가 없으면 운영자 휴대폰.
  2. 첫 3D 에셋 3MB 분배: 맵 1.5MB, 캐릭터 1.5MB(005). 경기장·섬 0.5MB는 첫 이동 뒤에 받는다.
  3. 돌처럼 내구가 2 이상인 블록: 남은 내구 단계마다 금 간 모습을 보인다(판정은 004 그대로).
  4. 섬·배경: 경기장은 하늘에 뜬 섬, 하늘·조명은 그 방 테마 분위기(카페 해 질 녘, 도서관 밤, 정원 낮).
  5. 옛 방 호환: 가구 id 12개를 유지하고 모델만 바꾼다. 고정 인테리어는 테마 모습이고 방 데이터가 아니며 충돌체를 더하지 않는다.

## 이유

- 006이 블록 종류를 늘리고 005가 캐릭터를 바꾸기 전에 예산이 있어야 두 작업이 같은 상한을 나눠 쓴다.
- 기준선에서 고칠 것이 이미 보였다: 그림자 패스가 본 패스보다 큼(도서관 47 대 16 드로우), 경기장에서 보이지 않는 방 그림자를 그림,
  블록 수가 바뀔 때마다 인스턴스 메시를 새로 만듦(코드 확인, 컨테이너에서는 렌더 비용에 가려 측정되지 않음).
- 드로우콜·삼각형·텍스처는 소프트웨어 WebGL에서도 실제 값이라 CI에서 판정할 수 있다. 프레임은 그렇지 않다(004 T056).

## 검토한 대안

- 프레임을 CDP CPU 감속으로 판정: GPU가 소프트웨어라 휴대폰과 상관이 없어 기각.
- 3MB를 캐릭터에 더 주기(2:1): 실내 인테리어가 늘어 맵 쪽이 더 필요해 반반. 005가 바꾸자고 하면 합 3MB 안에서 함께 고친다.
- 블록 손상 단계 없이 색만: 내구 4인 돌이 몇 번 남았는지 안 보여 기각.
